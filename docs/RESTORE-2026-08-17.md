# Restore log — 2026-08-17

This file documents a restore event for the Node-RED deployment on the
author's RPi5. The deployment itself is unchanged from upstream
`4e17b49`; this commit only adds an audit log so the restore can be
verified from git history alone.

## What happened

The Node-RED container `nodered` had been lost together with the
USB-backed `/mnt/data` mount. The Windows client's SSH tunnel
(`ssh -N -L 1880:127.0.0.1:1880 hermes-pi@192.168.0.205`) returned
`channel N: open failed: administratively prohibited` even after the
container was back up. Two separate problems had to be fixed.

## Restored state

- Container `nodered` is up on `127.0.0.1:1880` (verified via
  `podman ps`, `curl http://127.0.0.1:1880/`, and the user's
  successful access on Windows).
- Dashboard palette `node-red-dashboard` v3.6.6 installed and
  symlinked into the persistent volume at
  `/home/hermes-pi/nodered-data/node_modules/node-red-dashboard`.
- `flows.json` (18.1 K) is loaded into `/data/flows.json`.

## Companion fix

The SSH tunnel still required the master sshd to accept
`AllowTcpForwarding local` and `PermitOpen 127.0.0.1:1880`. The
host's sshd hardening drop-in (the operator's, not this repo's)
sets `AllowTcpForwarding no`, which blocks any port forwarding.

A local override was installed at
`/etc/ssh/sshd_config.d/50-nodered-tunnel.conf`. **No file in this
repository is part of the fix** — it's a host-config change that
needs to be reapplied on every reflash.

A copy of that file is kept at `~/sshd-config-fix/nodered-tunnel.conf`
on the Pi for reapplication.

## Bridge mount

`/mnt/data` was missing. To keep the disk-usage gauges functional, a
bind mount was set up as a temporary bridge:

```
sudo mount --bind /mnt/hermes-backup-usb /mnt/data
```

This is **not** a permanent fix — it does not survive a reboot and
points at the recovery USB rather than the historical /mnt/data
storage. When the original /mnt/data is recovered (or a fresh USB is
provisioned), update `/etc/fstab` and remove the bind source.

## Verification

```text
podman ps -a --filter name=nodered             # Up, <recently>
podman inspect nodered ... .NetworkSettings.Ports  # 127.0.0.1:1880:1880
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:1880/  # 200
sudo sshd -t                                   # silent = OK
sudo sshd -T | grep -iE 'forward|permit'       # allowtcpforwarding local; permitopen 127.0.0.1:1880
ssh -N -L 1880:127.0.0.1:1880 hermes-pi@192.168.0.205  # tunnel OK
http://127.0.0.1:1880/ui/                      # dashboard renders
```

## Recovery command (manual)

```bash
# 1. mount the recovery USB at /mnt/data if not already
sudo mount --bind /mnt/hermes-backup-usb /mnt/data

# 2. (re)install the sshd override if it was lost
sudo cp ~/sshd-config-fix/nodered-tunnel.conf \
        /etc/ssh/sshd_config.d/50-nodered-tunnel.conf
sudo chmod 644 /etc/ssh/sshd_config.d/50-nodered-tunnel.conf
sudo sshd -t
sudo kill -HUP $(pidof sshd | head -n 1)

# 3. bring up the container (idempotent)
./run.sh
```
